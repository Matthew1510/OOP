# Как работает LogiCoreSystem

## Запуск

Точка входа находится в `App/Program.cs`. Она создаёт `ConsoleApplication`
и запускает его метод `Run()`.

Обычный запуск выводит приветствие и открывает интерактивный режим:

```bash
dotnet run --project App/LogiCore.App.csproj
```

Чтобы сначала выполнить команды из файла, передайте путь после `--`:

```bash
dotnet run --project App/LogiCore.App.csproj -- Docs/my-commands.txt
```

Файл `Docs/demo-input.txt` содержит короткий сценарий: создание двух заказов
с обычным и скоропортящимся грузом, ручное и автоматическое назначение
транспорта, запуск и завершение доставок. Файл копируется в каталог сборки.

При создании `ConsoleApplication` создаётся `ConsoleContext`. В контексте
создаются репозитории клиентов, заказов и транспорта, а также `DeliveryService`.
Затем приложение создаёт шесть начальных машин через фабрики: два грузовика,
рефрижератор, самолёт, корабль и дрон. Машины добавляются в общий репозиторий,
который также использует сервис доставки.

Подписчики `ConsoleNotifier` выводят события, а `EventFileLogger` записывает их
в файл `logs/events.log` рядом с исполняемым приложением. Они работают во время
интерактивных операций; встроенный демонстрационный сценарий удалён.

Если задан путь к файлу команд, приложение выполняет команды из этого файла,
а затем переходит в интерактивный режим. Команда ищется по имени без учёта регистра и запускается через
`IConsoleCommand.Execute(context)`. Если команда или бизнес-операция выбрасывает
исключение, приложение показывает его сообщение и продолжает работу.
Пустая строка игнорируется; `exit` или закрытие ввода завершает цикл.

## Команды

| Команда | Действие |
| --- | --- |
| `help` | Вывести доступные команды |
| `interfaces` | Показать ковариантность репозитория и контравариантность валидатора (T3) |
| `vehicles` | Показать начальный парк и текущее состояние машин |
| `create` | Создать клиента, выбрать тип груза, задать маршрут и создать заказ |
| `orders` | Показать заказы, статусы, назначенные машины и стоимость |
| `assign` | Назначить выбранную машину заказу |
| `autochoose` | Назначить самую дешёвую подходящую свободную машину |
| `start` | Начать доставку назначенной машины |
| `complete` | Завершить доставку, освободить машину и учесть выручку |
| `cancel` | Отменить ещё не начатый заказ |
| `exit` | Выйти из приложения |

## Файловый сценарий

Команда `interfaces` демонстрирует присваивание
`IReadOnlyRepository<Customer>` в `IReadOnlyRepository<IIdentifiable>` и
`IValidator<Cargo>` в `IValidator<PerishableCargo>`. Для запуска другого файла
выполните:

```bash
dotnet run --project App/LogiCore.App.csproj -- Docs/my-commands.txt
```

Файл `Docs/demo-input.txt` содержит короткий пример: создание двух заказов,
ручное и автоматическое назначение транспорта и завершение доставок. Его можно
запустить той же командой, передав путь к файлу.

При автоматическом назначении диспетчер перебирает свободный транспорт, проверяет
совместимость и вместимость, вычисляет стоимость доступными типами транспорта
и выбирает самый дешёвый вариант. Ввод в файле сценария соответствует вопросам
команд `create` и `assign`; при изменении этих команд файл ввода следует
синхронно обновить.

## Жизненный цикл заказа

1. Введите `create`. Приложение запросит имя и контакт клиента, предложит
   выбрать один из пяти типов груза, а затем запросит общие характеристики.
   Для скоропортящегося груза указываются срок годности и температура; для
   хрупкого — уровень хрупкости; для опасного — класс опасности; для
   негабаритного — длина, ширина и высота. Затем можно отдельно выбрать
   страхование и приоритетную доставку.
2. Создаются `Customer`, выбранный наследник `Cargo` через `CargoFactory` и
   `Route`. Маршрут строится от
   координат `(0, 0)` до введённой конечной точки. `DeliveryService`
   проверяет груз и создаёт `Order`.
3. Заказ добавляется в `ConsoleContext.Orders`, клиент — в
   `ConsoleContext.Customers`. Конструктор `Order` также связывает заказ с
   клиентом и добавляет его в историю `Customer.OrderHistory`.
4. Для назначения вручную выполните `assign` и укажите номер заказа и машины.
   Для автоматического выбора выполните `autochoose` и укажите номер заказа.
   Сервис проверяет совместимость, состояние и вместимость транспорта,
   рассчитывает стоимость через стратегию тарифа и выбранные декораторы услуг,
   затем меняет статус заказа на `Assigned`. Команда выводит промежуточную
   стоимость после каждого шага.
5. Команда `start` переводит заказ в `InTransit`, а машину — в `InTransit`.
6. Команда `complete` переводит заказ в `Delivered`, освобождает машину и
   прибавляет стоимость заказа к `DeliveryService.Revenue`.

Заказ можно отменить в статусе `Created` или `Assigned`. Если машина уже была
назначена, при отмене она освобождается. Доставку в пути отменить нельзя.

## Где находятся данные

Данные существуют только в памяти процесса и хранятся в собственной
обобщённой коллекции `Repository<T>`:

- `ConsoleContext.Vehicles` (`Repository<Vehicle>`) — машины;
- `ConsoleContext.Orders` (`Repository<Order>`) — заказы;
- `ConsoleContext.Customers` (`Repository<Customer>`) — клиенты;
- `Order.Cargo` — грузы конкретного заказа;
- `Customer.OrderHistory` — история заказов клиента;
- `DeliveryService.Revenue` — выручка завершённых доставок.

Файлового или серверного хранилища приложение не использует. После `exit` все
созданные заказы, клиенты и выручка теряются. Машины создаются заново при каждом
запуске. `DeliveryService` использует тот же экземпляр репозитория машин, что и
`ConsoleContext`, поэтому при автоназначении видит весь парк. Репозиторий
предоставляет добавление и удаление по `Guid`, поиск по `Guid`, фильтрацию и
перебор элементов; порядковый номер CLI преобразуется в элемент через методы
`ConsoleContext.GetOrder` и `ConsoleContext.GetVehicle`.

## Слои и ответственность

- `App/Program.cs` и `App/Console/` запускают CLI и обрабатывают ввод/вывод.
- `App/Console/Commands/` содержит отдельные команды и читает проверенный ввод.
- `ConsoleContext` хранит данные текущего сеанса и предоставляет доступ к
  заказу или машине по порядковому номеру.
- `DeliveryService` координирует создание заказа, проверку совместимости,
  назначение машины, переходы статусов и выручку.
- `Domain/` содержит сущности и бизнес-правила: `Order`, `Customer`, `Cargo`,
  `Vehicle`, `Route`, валидатор и фабрики.

Порядковый номер, который CLI просит для заказа или машины, — это позиция в
списке текущего сеанса. У самих доменных объектов также есть уникальный `Guid`
`Id`.
